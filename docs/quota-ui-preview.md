# Quota UI preview

User-defined usage-quota forecasting is the approved product direction (confirmed 2026-10-29). This document describes the implemented preview, not production tracking. It does not mark roadmap D2–D9 integrations complete. PET means when device-measured mobile consumption reaches the chosen amount, not carrier allowance depletion. Freebie traffic counts when measured; no billing-bucket classification, carrier reconciliation or network enforcement is provided.

The quota flow follows Direction C: off-white background, white surfaces and forecast hero, navy text/actions, teal progress, soft blue information panels and mint selected navigation. A slim progress indicator accompanies the hero metrics; there is no circular gauge. Quota shapes use 16dp controls, 20dp cards and a 24dp hero. Authentication and launch retain dark navy. `QuotaTheme` scopes the palette and system bars; shared components respect their enclosing theme. No theme toggle is planned. See [UI design](ui-redesign.md) and [brand assets](brand-assets.md).

History is available through the floating bottom navigation. Since D7 it shows real data: 24-hour (hourly), 7-day and per-cycle (daily) Vico charts of measured mobile usage, with unmeasured periods left blank, a total and average over the measured time, the peak period, an exact-readings sheet that says "Not measured" for gaps, every quota cycle with its progress, and read-only cycle details. Reached cycles compare the earlier PET with the actual reach. See [history](history.md).

Notifications open from the bell on Home and History. Since D8 the center shows real quota alerts from Room `notifications`: 75%, 90% and 100% milestones and forecast alerts when the PET is within 24 hours and within 3 hours, each once per cycle. Opening an alert sets its `read_at` and offers **View quota details** (the current cycle's Quota Details, or read-only details of a past cycle). All/Unread filters, mark-all-read, the empty state and unread badges read the same rows. The same alerts are posted as Android notifications when allowed; see [quota alerts](notifications.md). Returning from notifications to History preserves its filters and scroll position.

After signing in, Home replaces the old dashboard placeholder. Create a quota in MB or GB (decimal units) with an optional name. The form starts a real tracking cycle (D3, see [quota cycles](quota-cycles.md)); Home's preview fixtures follow it into the collecting state until D5 connects Home. Back cancels the form. Draft input survives configuration changes.

When the signed-in user has a real cycle, Home's hero shows it with the on-device forecast (D6, see [forecast](forecast.md)): the estimated time to quota, "Beyond 30 days", "Collecting usage" while fewer than 6 of the last 24 hours are measured, or "Forecast unavailable". Otherwise use **Preview options** on Home to review no active quota, collecting usage, forecast available, missing permission, and quota reached; those forecasts are fixtures, not inference. The 7-day chart shows History's real daily totals with the same colours (today amber, dashed daily average). Sample quota state survives activity recreation through SavedStateHandle; there is no persistent quota database or history.

Settings is a real navigation destination with a Profile subpage, milestone/forecast switches persisted in Room `notification_preferences` (D8), real tracking status (service, Usage Access, notifications, battery optimization) with a link to Tracking setup, a "Not synced yet" cloud sync card (C3 pending), version information (tapped 7 times it opens the hidden [ML diagnostics](diagnostics.md)) and preview privacy information. The display name is loaded from `public.users.name` (set at sign-up or from Google) and saved back to it; the username is shown read-only. Account email is read-only and comes from the existing signed-in session. The switches turn each kind of alert on or off; when Android notifications are off, Settings says so and offers **Allow notifications**. Sign-out requires confirmation, uses existing Supabase Auth, disables repeated submissions while pending and navigates away only on success; failures remain visible in the confirmation dialog. Settings and Profile retain the floating bottom navigation with Settings selected.

Use **View quota details** below the quota summary. Details shows the device's latest real cycle: quota, used and remaining data measured from the 10-minute readings, when usage was last measured, any unmeasured time, start/reached/ended times and status. The forecast card shows the same on-device forecast as Home for an active cycle. **End cycle** requires confirmation; the ended cycle stays on Details. **Create another quota** opens the form, and starting it ends any current cycle. Cycles are stored in Room, so they survive process death and reboots; History lists every cycle and opens read-only details of each (D7).

Home's **About Usage Access** (missing-permission scenario) and Settings → **Open tracking setup** open the real Tracking setup screen from D4: Usage Access, notification and phone-state permissions, the battery-optimization exemption, and start/stop of measurement. Measurements feed Quota Details, Home's hero and History; Home's 7-day card uses the same daily totals as History; see [usage telemetry](telemetry.md). No backend schema or model changes are included. No quota caps or throttles network traffic.

Compose previews cover all Home states, Create Quota, enlarged fonts and landscape Home. Unit tests cover numeric conversion, invalid input and sample-state restoration; instrumentation tests cover state rendering and form submission.
